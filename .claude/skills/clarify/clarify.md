# Step 1 — Clarify Assumptions

Before doing anything else, ask questions to surface hidden assumptions. Do not proceed to
planning until the user has answered (or explicitly said to skip).

## Questions to ask (pick the ones relevant to this task)

- What is the expected input/output or user-facing behaviour?
- Are there edge cases or constraints I should handle?
- Should this integrate with existing code, or is it greenfield?
- Are there specific files, modules, or patterns I should follow?
- Any performance, security, or accessibility requirements?
- Should tests be written? What kind (unit, integration, e2e)?
- Are there acceptance criteria or a definition of done?

## Format rules

- Ask as a numbered list
- Keep questions concise
- If the feature request is already very detailed, confirm your understanding instead of asking redundant questions
- **Do not proceed to Step 2 until the user has responded**
